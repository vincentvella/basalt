# Website

basaltjs.dev: [Next.js](https://nextjs.org) and
[Fumadocs](https://fumadocs.dev), with Tailwind and Biome. The same stack the
other sites here use, which is the reason it is this one.

## Running it

```bash
npm install
npm run dev
```

`npm run build` writes the production build, and `npm run typecheck` runs the
same type check CI does. `npm run lint` is Biome; `npm run format` applies it.

## Two docs trees

`/docs` is written for somebody building an app and lives in `content/docs` as
MDX, because several of those pages are more than prose: the support table is
generated with a bar per host, and Getting started renders the version matrix
out of the file the build enforces.

`/contributing` is the repository's own `docs/` folder. Those stay plain
markdown where they are, because they are read on GitHub at least as often as
here, and `scripts/sync-docs.mjs` turns them into the site's second tree before
every build: frontmatter from each file's heading, the sidebar order, and links
rewritten for the site. It also copies in
`packages/basalt-core/supported-versions.json`, which the version matrix
renders, because the bundler resolves nothing outside this directory.

So `content/contributing/` and `lib/supported-versions.json` are generated and
git-ignored. Everything else under `content/` is written by hand.

Two pages come from the repository rather than from here and are generated by
`scripts/check_support.js`: `content/docs/support.mdx` and the numbers the
landing page quotes, in `lib/support.json`. Run that script after changing
`docs/platform-support.json`; CI fails if either is stale.

## Deployment

The site is a Vercel project (`basalt`, root directory `website`), serving
basaltjs.dev. **A push does not deploy it, on any branch.** `vercel.json` turns
the git integration off:

```json
{ "git": { "deploymentEnabled": false } }
```

Every branch, not just `main`, because a preview deployment is a build like any
other: pushing the `ci` branch or opening a pull request would otherwise cost
one. Deploying from the CLI is unaffected, that not being the git integration.

Why: the site renders `website/**` and `../docs`, and `scripts/sync-docs.mjs`
skips `BACKLOG.md`, `backlog/**` and `ci-performance.md` from the latter.
Almost every commit in this repository touches one of those excluded files and
nothing else the site renders, so auto-deploying on push rebuilt an identical
site about twenty times a day. The numbers are in `docs/ci-performance.md`.

To ship it:

```bash
gh workflow run site.yml
```

or Actions → **Deploy site** → Run workflow. It builds the site on the runner
and hands Vercel the finished thing with `vercel deploy --prebuilt`, so Vercel
builds nothing and the deploy costs no Vercel build minutes. Then it asks
basaltjs.dev for five paths and fails if any of them is not a 200, because a
deploy that returns a URL and serves a 404 looks fine from the command line.

It used to be `npx vercel --prod` from this directory, which built on Vercel
and could only be done from a machine logged in to it. The workflow needs a
`VERCEL_TOKEN` repository secret; the project and team ids are in
`.github/workflows/site.yml`, which is where you can see which project a run
ships.

The GitHub Actions `Docs` workflow still builds the site on every push that
changes something it renders, so a commit that breaks the build says so on the
commit. What it does not do is deploy, which is the one thing that is asked
for.
