# Title bar

The window's title bar: its title, its colours, and whether the host draws it or
the app does.

```js
import {TitleBar, useTitleBar, useTitleBarMetrics, windowControl} from 'basalt-core';
```

```jsx
<TitleBar title="Inbox" backgroundColor="#1f1f1f" textColor="#fff" />
```

```js
useTitleBar({title: 'Inbox', backgroundColor: '#1f1f1f'});
```

The component and the hook are the same thing. `<TitleBar>` renders nothing and
exists because a screen declaring its own header reads better as an element than
as a call.

| option | |
| --- | --- |
| `title` | the window's title |
| `style` | `'native'` or `'hidden'` |
| `backgroundColor` | any React Native colour |
| `textColor` | |
| `borderColor` | |

Colours are honoured on all three desktops, alpha included on Linux, where a
header bar can be translucent in a way a Windows caption cannot.

## Requests stack

Exactly as `<StatusBar>`'s do: the most recently mounted request wins, key by
key, and unmounting one restores what was beneath it. So a screen can colour the
title bar without knowing what the screen behind it asked for, and going back
puts it right.

## `style: 'hidden'`

The system title bar is removed, the app's own content reaches the top of the
window, and the host still draws the minimise, maximise and close buttons over
the top right corner. What the app then owes is a header of its own, and the
marks that say which parts of it drag the window:

```jsx
const {height, buttonsWidth} = useTitleBarMetrics();

<TitleBar style="hidden" />
<TitleBar.DragRegion style={{height, paddingRight: buttonsWidth}}>
  <Text>Inbox</Text>
  <TitleBar.NoDragRegion>
    <Button title="Compose" />
  </TitleBar.NoDragRegion>
</TitleBar.DragRegion>
```

`useTitleBarMetrics()` answers how much of the window the caption takes:
`{height, buttonsWidth, style}`, both measurements in layout units. Padding the
header by `buttonsWidth` is what keeps an app's own controls out from under the
system's.

The caption buttons an app draws for itself act through `windowControl`:

```js
windowControl.minimize();
windowControl.toggleMaximize();
windowControl.close();
```

:::caution
`<TitleBar.DragRegion>` is where the three are not yet equal. Windows and Linux
read the marks and drag the window from them. macOS does not read them yet, so a
header an app drew there shows correctly but does not move the window.
:::

## On a host that has none

Every call is guarded: on a host with no title bar module, or before it has
registered one, a call is ignored and the metrics are all zero. All three
desktops do have one, and the guard is what lets the same code run before the
host is up without a branch in the app.
