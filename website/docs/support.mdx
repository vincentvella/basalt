# Platform support

Three desktops, three native toolkits, and not the same amount finished on
each. One row per attribute, with anything short of done linking to the entry
that says what is missing and which call would do it.

The attributes are React Native's own, read out of its declarations rather than
listed here: `scripts/scrape_props.py` scrapes React Native 0.87.1
and this renders what it found, so a prop added upstream turns up as a row
with no status and fails the check until somebody fills it in.

**Every style name a `<View>` or a `<Text>` takes has a row.** Most are
fields in one of ReactCommon's prop structs. The rest belong to Yoga:
`padding`, `margin`, `flex`, `inset`, `gap` and their spellings, which no
struct declares one by one, because `YogaStylableProps` carries a single
`yogaStyle` field. Those names come from React Native's own
`____LayoutStyle_Internal` and sit in a section of their own. A handful are
declared in JavaScript and read by no struct at all, and they are listed too,
because an app can still write them.

The scrape reports any style name that is none of those three, which is what
makes this list complete rather than long: the layout props were missing from
this page until somebody went looking for `padding`, and nothing could have
said so.

**What is not here yet**: the props of a `<TextInput>`, which has
ReactCommon structs of its own that nothing scrapes, so some thirty names an
app writes on one have no row. `backlog/textinput.md` records it with the
shape of the fix, which is the one `<Image>` and the layout props already
had.

Each struct is split the way reactnative.dev splits a component page: the
style props a `style={{...}}` takes, then the props written on the element
itself. That split is read from React Native too, out of the Flow types that
declare both, so a prop that moves between them moves here. Where
ReactCommon spells a prop differently from JavaScript, the name an app writes
is the one in the row and ReactCommon's is under it; where several names land
in one field, as thirteen corner radii land in `borderRadii`, they are listed
under the row that implements them.
